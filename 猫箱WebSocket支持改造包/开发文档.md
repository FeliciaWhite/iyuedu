# 阅读 APP WebSocket TTS 改造开发文档

## 一、项目背景

本项目基于开源阅读 APP（Legado）进行二次开发。Legado 的在线朗读功能通过 **HTTP 朗读引擎** 实现：用户在 APP 里配置一个 TTS 引擎，填写 `url`、`contentType` 等字段，APP 在朗读时向该 URL 发送请求获取音频文件。

### 1.1 原始架构

原始的 `HttpReadAloudService.kt` 中，获取音频的核心方法是 `getSpeakStream`：

```kotlin
private suspend fun getSpeakStream(
    httpTts: HttpTTS,
    speakText: String
): InputStream? {
    if (httpTts.url.startsWith("ws://") || httpTts.url.startsWith("wss://")) {
        // 只有 WebSocket 类型的 URL 才走 WebSocket 分支
        // 且只能在 loginCheckJs 里执行 JS，JS 只能返回 InputStream 或 ByteArray
        val jsStr = httpTts.loginCheckJs
        if (!jsStr.isNullOrBlank()) {
            try {
                val jsResult = httpTts.evalJS(jsStr) {
                    put("speakText", speakText)
                    put("speechRate", speechRate)
                    put("ws", TtsWebSocketHelper())
                }
                when (jsResult) {
                    is InputStream -> return jsResult
                    is ByteArray -> return ByteArrayInputStream(jsResult)
                }
            } catch (e: Exception) {
                AppLog.put("TTS WebSocket JS错误: ${e.localizedMessage}", e)
            }
        }
        return getSpeakStreamViaWebSocket(httpTts, speakText)
    }
    // HTTP/HTTPS 分支：用 AnalyzeUrl 发送 HTTP 请求
    while (true) {
        try {
            val analyzeUrl = AnalyzeUrl(
                httpTts.url,
                speakText = speakText,
                speakSpeed = speechRate,
                ...
            )
            var response = analyzeUrl.getResponseAwait()
            ...
            return response.body.byteStream()
        } catch (e: Exception) {
            // 重试逻辑...
        }
    }
}
```

### 1.2 原始架构的局限

| 问题 | 说明 |
|---|---|
| **JS 只能做"辅助"** | `loginCheckJs` 只能返回 `InputStream` 或 `ByteArray`，如果失败，APP 仍然会继续调用 `getSpeakStreamViaWebSocket`，无法完全接管 |
| **没有 JS 沙箱工具** | JS 代码里无法直接创建 `ByteArrayOutputStream`（Rhino 沙箱没有 `java.io` 包），也无法发起 WebSocket 连接 |
| **WebSocket 逻辑写死在 APP 里** | `getSpeakStreamViaWebSocket` 里的协议处理、参数拼接、消息收发都是 Kotlin 硬编码，用户无法自定义 |
| **无法按需拆分文本** | 比如想实现"引号外用 A 发音人，引号内用 B 发音人"，原始架构做不到 |
| **不支持提示词等扩展字段** | 猫箱 API 的 `context_texts` 等字段无法通过配置传递，必须改源码 |

## 二、改造思路

### 2.1 总体设计

让 **HTTP 朗读引擎的 `url` 字段支持 `@js:` 前缀**。当 `url` 以 `@js:` 开头时，后面的内容是一段 JavaScript 代码。APP 执行这段 JS，JS 可以：

1. **完全接管音频合成** —— 调用 `ws.maoxiang()` 获取音频 `byte[]`，拼接多段音频后直接返回
2. **动态生成 URL** —— 返回一个 `String`，APP 把它当成普通 URL 继续处理
3. **返回音频流** —— 返回 `InputStream` 或 `ByteArray`，APP 直接播放

### 2.2 注入给 JS 的环境变量

执行 JS 时，向作用域注入以下变量：

| 变量名 | 类型 | 说明 |
|---|---|---|
| `speakText` | `String` | APP 传入的当前段落文字 |
| `speechRate` | `Int` | APP 朗读设置里的语速值（0~100） |
| `ws` | `TtsWebSocketHelper` | 供 JS 调用的 WebSocket 工具对象 |

### 2.3 新增 `TtsWebSocketHelper` 类

这是一个 Kotlin 类，用 `@Keep` 注解防止 ProGuard 混淆（Rhino 反射调用需要类名不被混淆）。它提供以下方法供 JS 调用：

| 方法 | 说明 |
|---|---|
| `maoxiang(..., extraPayload)` | 连接猫箱 WebSocket，完成一段文本的合成，返回 `byte[]` |
| `newBuffer()` | 创建 `ByteArrayOutputStream`，用于拼接多段音频 |
| `mergeAudio(audio1, audio2, ...)` | 合并多个 `byte[]` |

### 2.4 `@js:` 执行失败的处理

原始代码里 `@js:` 执行失败后只记录日志，代码继续往下走进入 HTTP 分支。HTTP 分支里的 `AnalyzeUrl` 会再次执行那段 JS，但 `AnalyzeUrl.evalJS()` 没有注入 `ws`，导致报 `ReferenceError: "ws"未定义` 并弹窗。

**修复**：`@js:` 执行失败后直接 `return`，不再进入 HTTP 分支。同时增加重试循环，按 APP 设置里的重试次数自动重试。

## 三、具体代码修改

### 3.1 新增文件：`TtsWebSocketHelper.kt`

**路径**：`app/src/main/java/io/legado/app/help/tts/TtsWebSocketHelper.kt`

这个文件是全新创建的，不需要基于原有代码修改。核心功能：

1. **独立的 OkHttpClient**：不受 Legado 协程生命周期影响，避免 Service 销毁时 WebSocket 被中断
2. **猫箱协议封装**：连接 WebSocket → 发送 `StartTask` → 收到 `TaskStarted` 后发送文本和 `FinishTask` → 收取 Base64 音频数据 → 返回 `byte[]`
3. **`extraPayload` 通用扩展**：最后一个参数是 JSON 字符串，解析后自动合并到 `payload` 根对象

```kotlin
package io.legado.app.help.tts

import androidx.annotation.Keep
import io.legado.app.constant.AppLog
import io.legado.app.exception.NoStackTraceException
import okhttp3.OkHttpClient
import okhttp3.Request
import okhttp3.Response
import okhttp3.WebSocket
import okhttp3.WebSocketListener
import okio.ByteString
import org.json.JSONObject
import java.io.ByteArrayOutputStream
import java.util.concurrent.CountDownLatch
import java.util.concurrent.TimeUnit

/**
 * TTS WebSocket 辅助工具，供 JS 脚本调用。
 * 完全独立的 OkHttpClient，不受 Legado 协程生命周期影响。
 */
@Keep
class TtsWebSocketHelper {

    /**
     * 猫箱 WebSocket TTS 合成（同步阻塞）。
     *
     * @param wsUrl        WebSocket 连接地址
     * @param speakText    要合成的文本
     * @param voice        发音人 ID
     * @param format       音频格式，如 "mp3"
     * @param sampleRate   采样率，如 24000
     * @param speechRateFactor 语速因子，如 1.15
     * @param pitchValue   音调值，如 0
     * @param appkey       appkey
     * @param timeoutMs    超时毫秒
     * @param extraPayload 额外字段（JSON字符串），自动合并到 payload 根对象
     * @return 音频 ByteArray，失败返回 null
     */
    fun maoxiang(
        wsUrl: String,
        speakText: String,
        voice: String,
        format: String,
        sampleRate: Int,
        speechRateFactor: Double,
        pitchValue: Int,
        appkey: String,
        timeoutMs: Long,
        extraPayload: String? = null
    ): ByteArray? {
        // ... 实现详见源码文件 ...
    }

    fun newBuffer(): java.io.ByteArrayOutputStream = java.io.ByteArrayOutputStream()

    fun mergeAudio(vararg audios: ByteArray): ByteArray {
        val out = java.io.ByteArrayOutputStream()
        audios.forEach { out.write(it) }
        return out.toByteArray()
    }
}
```

**关键设计点**：

- `@Keep` 注解：防止 ProGuard/R8 混淆类名和方法名，否则 Rhino JS 引擎通过反射找不到方法
- 独立的 `OkHttpClient`：用 `CountDownLatch` 做同步阻塞，JS 是同步执行的，必须等 WebSocket 合成完才能返回
- `extraPayload` 解析：
  ```kotlin
  if (!extraPayload.isNullOrBlank()) {
      val extra = JSONObject(extraPayload)
      extra.keys().forEach { key ->
          put(key, extra.get(key))
      }
  }
  ```
  这段代码把 JS 传来的任意 JSON 字段合并到 API payload 里，以后猫箱 API 新增任何字段都不需要改 Kotlin 源码

### 3.2 修改文件：`HttpReadAloudService.kt`

**路径**：`app/src/main/java/io/legado/app/service/HttpReadAloudService.kt`

#### 修改点 A：import 增加 TtsWebSocketHelper


#### 修改点 B：`getSpeakStream` 方法增加 `@js:` 前缀支持

**原始代码**（简化）：

```kotlin
private suspend fun getSpeakStream(
    httpTts: HttpTTS,
    speakText: String
): InputStream? {
    if (httpTts.url.startsWith("ws://") || httpTts.url.startsWith("wss://")) {
        // WebSocket 分支...
    }
    // HTTP 分支...
}
```

**修改后代码**：

```kotlin
private suspend fun getSpeakStream(
    httpTts: HttpTTS,
    speakText: String
): InputStream? {
    var ttsUrl = httpTts.url

    // 【新增】支持 @js: 前缀：先执行 JS 获取实际 URL 或音频流
    if (ttsUrl.startsWith("@js:")) {
        val jsCode = ttsUrl.substring(4)
        var retryCount = 0
        while (true) {
            try {
                val jsResult = httpTts.evalJS(jsCode) {
                    put("speakText", speakText)      // 注入当前段落文字
                    put("speechRate", speechRate)    // 注入语速
                    put("ws", TtsWebSocketHelper())  // 注入 WebSocket 工具对象
                }
                when (jsResult) {
                    is InputStream -> return jsResult
                    is ByteArray -> return ByteArrayInputStream(jsResult)
                    is String -> {
                        ttsUrl = jsResult
                        break
                    }
                }
            } catch (e: Exception) {
                retryCount++
                if (retryCount > AppConfig.ttsRetryCount) {
                    // 重试次数用完
                    if (AppConfig.ttsRetrySkipOnFail) {
                        // 返回静音音频，不停止朗读
                        return ByteArrayInputStream(BaseReadAloudService.generateSilentWavBytes(50))
                    } else {
                        throw NoStackTraceException("TTS合成失败: ${e.localizedMessage}")
                    }
                }
                delay(1000)  // 等1秒再重试
            }
        }
    }

    if (ttsUrl.startsWith("ws://") || ttsUrl.startsWith("wss://")) {
        // WebSocket 分支...（原有逻辑保留）
    }
    // HTTP 分支...（原有逻辑保留）
}
```

#### 修改点 C：`getSpeakStreamViaWebSocket` 增加 `url` 参数

因为 `@js:` 可能返回一个 String 来替换 URL，所以 `getSpeakStreamViaWebSocket` 需要接收处理后的 URL：

```kotlin
private suspend fun getSpeakStreamViaWebSocket(
    httpTts: HttpTTS,
    speakText: String,
    url: String = httpTts.url  // 新增参数，默认取原始 url
): InputStream? = withContext(Dispatchers.IO) {
    val ttsUrl = url  // 使用传入的 url（可能已被 @js: 处理过）
    // ... 原有逻辑 ...
}
```

同时 `getSpeakStream` 里调用它时传入 `ttsUrl`：

```kotlin
return getSpeakStreamViaWebSocket(httpTts, speakText, ttsUrl)
```

## 四、如何在自己的项目中集成

如果你的项目也是基于 Legado 或类似的 Android 阅读 APP，想添加同样的 WebSocket TTS 支持，按以下步骤操作：

### 步骤 1：创建 `TtsWebSocketHelper.kt`

在 `app/src/main/java/io/legado/app/help/tts/` 目录下（或你项目的对应目录）创建 `TtsWebSocketHelper.kt`，内容直接使用源码文件中的完整代码。

**必须加 `@Keep` 注解**：
```kotlin
@Keep
class TtsWebSocketHelper {
    ...
}
```

如果项目开启了 ProGuard/R8 混淆，没有这个注解 Rhino JS 引擎会找不到类和方法。

### 步骤 2：修改 `HttpReadAloudService.kt`

找到 `getSpeakStream` 方法，在方法开头添加 `@js:` 前缀处理逻辑：

```kotlin
var ttsUrl = httpTts.url

if (ttsUrl.startsWith("@js:")) {
    val jsCode = ttsUrl.substring(4)
    var retryCount = 0
    while (true) {
        try {
            val jsResult = httpTts.evalJS(jsCode) {
                put("speakText", speakText)
                put("speechRate", speechRate)
                put("ws", TtsWebSocketHelper())
            }
            when (jsResult) {
                is InputStream -> return jsResult
                is ByteArray -> return ByteArrayInputStream(jsResult)
                is String -> {
                    ttsUrl = jsResult
                    break
                }
            }
        } catch (e: Exception) {
            retryCount++
            if (retryCount > AppConfig.ttsRetryCount) {
                if (AppConfig.ttsRetrySkipOnFail) {
                    return ByteArrayInputStream(BaseReadAloudService.generateSilentWavBytes(50))
                } else {
                    throw NoStackTraceException("TTS合成失败: ${e.localizedMessage}")
                }
            }
            delay(1000)
        }
    }
}
```

**注意**：如果你的项目没有 `AppConfig.ttsRetryCount` 和 `AppConfig.ttsRetrySkipOnFail`，可以用常量代替，或者从设置中读取。

### 步骤 3：确保 `getSpeakStreamViaWebSocket` 支持传入 url 参数

修改 `getSpeakStreamViaWebSocket` 的签名，增加 `url: String = httpTts.url` 参数，并在方法内部使用这个 `url` 而不是 `httpTts.url`。

### 步骤 4：确保 ProGuard 不混淆 `TtsWebSocketHelper`

如果项目使用了 ProGuard/R8，在 `proguard-rules.pro` 中添加：

```proguard
-keep class io.legado.app.help.tts.TtsWebSocketHelper {
    <methods>;
}
```

或者直接在类上加 `@Keep` 注解（需要 `androidx.annotation.Keep` 依赖）。

### 步骤 5：编译测试

1. 在 APP 的朗读引擎设置里导入示例 JSON
2. 选择该引擎，开始朗读
3. 查看日志确认 WebSocket 连接和音频合成正常

## 五、朗读引擎配置写法

### 5.1 基本结构

```json
[
  {
    "id": 1748582400001,
    "name": "猫箱-温柔桃子/VV交替",
    "url": "@js:\n// JS代码写在这里\n...",
    "contentType": "websocket/maoxiang",
    "concurrentRate": "0",
    "lastUpdateTime": 1748582400001,
    "loginCheckJs": ""
  }
]
```

**关键**：`url` 字段以 `@js:` 开头，后面直接跟 JavaScript 代码。

### 5.2 JS 代码中的可用变量

| 变量 | 来源 |
|---|---|
| `speakText` | APP 注入，当前段落文字 |
| `speechRate` | APP 注入，语速值 |
| `ws` | APP 注入，`TtsWebSocketHelper` 实例 |

### 5.3 返回值规则

| 返回类型 | APP 行为 |
|---|---|
| `byte[]`（通过 `out.toByteArray()`） | 直接当成音频播放 |
| `InputStream` | 直接当成音频流播放 |
| `String` | 把 `url` 替换成这个字符串，继续走原有逻辑 |

### 5.4 完整示例说明

见 `示例配置/猫箱_温柔桃子_朗读引擎.json`，其核心逻辑：

1. **定义参数**：WebSocket 地址、音频格式、采样率、appkey、超时等
2. **定义发音人**：旁白用桃子，对话用 VV
3. **定义提示词**：桃子用"男性旁白朗读"，VV用"用夹子音朗读"
4. **按中文双引号拆分文本**：
   - 引号外的文字 → 旁白 → 桃子
   - 引号内的文字（含引号）→ 对话 → VV
5. **分别合成**：每段文字调用 `ws.maoxiang()` 合成，传入对应的 `voice` 和 `extraPayload`（提示词）
6. **合并音频**：用 `ws.newBuffer()` 创建缓存，把每段 `byte[]` 写入，最后返回合并后的 `byte[]`

### 5.5 `extraPayload` 用法

`ws.maoxiang()` 最后一个参数是 `extraPayload`，JSON 字符串格式：

```javascript
// 传提示词
var extra = '{"context_texts":["男性旁白朗读"]}';

// 同时传多个字段
var extra = '{"context_texts":["男性旁白朗读"],"emotion":"calm"}';

// 不传
var extra = null;
```

这些字段会自动合并到猫箱 API 的 `payload` 根对象里。

## 六、最终支持的功能

| 功能 | 说明 |
|---|---|
| **WebSocket TTS 合成** | 通过 `ws.maoxiang()` 直接连接猫箱 WebSocket API |
| **JS 完全接管合成** | `@js:` 前缀让 JS 代码完全控制音频获取流程 |
| **多段音频拼接** | `ws.newBuffer()` + `out.write()` 把多段音频合并成一个 |
| **多发音人切换** | 根据文本特征（如引号）动态选择不同发音人 |
| **提示词支持** | 通过 `extraPayload` 给不同发音人传不同提示词 |
| **通用字段扩展** | `extraPayload` 支持任意 JSON 字段，以后 API 升级不需要改 APP 源码 |
| **自动重试** | 网络错误或服务器繁忙时按设置自动重试 |
| **失败不中断** | 重试次数用完后可返回静音音频，朗读不停止 |
| **防封随机设备** | JS 里随机生成 `device_id` 和 `aid` |

## 七、常见问题

### Q1: JS 里为什么不能用 `new java.io.ByteArrayOutputStream()`？

Rhino JS 引擎运行在沙箱里，没有 `java.io` 包的访问权限。我们通过 `TtsWebSocketHelper.newBuffer()` 方法暴露了这个功能。

### Q2: 多段 MP3 直接二进制拼接会不会播放异常？

不会。猫箱 API 返回的是**流式裸 MP3 帧**（没有 ID3 头尾标签），每帧开头都有 `0xFFE` 同步标记。播放器会逐帧解析，自动衔接，完全无缝。

### Q3: 缓存是怎么工作的？

APP 的缓存文件名是按这段文字算的：
```kotlin
MD5Utils.md5Encode16("$ttsUrl-|$speechRate-$indexPart-|$speakText")
```

内部拆成几段合成对外部缓存完全透明，缓存的是一个合并后的完整音频文件。

### Q4: 如果猫箱 API 以后增加了新字段，需要改 APP 源码吗？

**不需要**。只要在 JS 里通过 `extraPayload` 传新字段即可。例如猫箱新增了 `emotion` 字段：

```javascript
var extra = '{"emotion":"happy"}';
ws.maoxiang(wsUrl, text, voice, format, sampleRate, rate, pitch, appkey, timeout, extra);
```

`TtsWebSocketHelper` 会自动把 `emotion` 字段合并到 API payload 里。

## 九、总结

本次改造的核心思路是：**把 TTS 合成的控制权从 Kotlin 代码下放到 JavaScript 配置里**。

- 新增 `TtsWebSocketHelper` 给 JS 提供底层能力（WebSocket 连接、音频缓存、音频合并）
- 修改 `HttpReadAloudService` 让 `url` 字段支持 `@js:` 前缀执行 JS
- JS 可以返回 `byte[]` 完全接管，也可以返回 `String` 动态生成 URL
- `extraPayload` 通用参数机制让后续扩展零成本

这样，所有与具体 TTS 服务（猫箱、其他 WebSocket TTS）相关的逻辑都可以写在 JSON 配置里，APP 源码保持通用，不需要为每个新需求重新编译 APK。
