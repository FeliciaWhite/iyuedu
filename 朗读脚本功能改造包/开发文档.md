# 阅读 APP 朗读脚本功能开发文档

## 一、功能概述

**朗读脚本**（TTS Script）是阅读 APP 的一个扩展功能，允许用户编写 JavaScript 代码，在朗读前对待朗读文本进行动态修改。脚本按顺序执行，每个脚本接收当前文本，返回修改后的文本。

### 典型应用场景

| 场景 | 脚本作用 |
|---|---|
| 删除段评/图片占位符 | 把 `袮`、`꧁` 等排版符号删掉 |
| 替换敏感词 | 把敏感词替换为谐音或星号 |
| 添加停顿标记 | 在句号后加换行，让 TTS 停顿更自然 |
| 角色标注 | 根据上下文判断说话人，在文本前加上 `[张三说：]` |
| 多音字纠正 | 把多音字替换为带拼音标注的形式 |

## 二、架构设计

### 2.1 整体流程

```
APP 获取段落文字
    ↓
applyTtsScripts(text)   ← 按顺序执行所有启用的朗读脚本
    ↓
脚本1: text = text.replace(...)
脚本2: text = text.replace(...)
脚本3: ...
    ↓
修改后的文字 → 继续走 TTS 合成流程
```

### 2.2 数据模型

`TtsScript` 实体类（Room 数据库）：

```kotlin
@Entity(tableName = "tts_scripts")
data class TtsScript(
    @PrimaryKey(autoGenerate = true)
    var id: Long = System.currentTimeMillis(),
    var name: String = "",           // 脚本名称
    var code: String = "",           // JS 代码
    var isEnabled: Boolean = true,   // 是否启用
    var order: Int = Int.MIN_VALUE   // 排序顺序
)
```

### 2.3 核心执行逻辑

`BaseReadAloudService.applyTtsScripts()` 是朗读脚本的执行引擎：

```kotlin
protected fun applyTtsScripts(text: String): String {
    if (text.isEmpty() || text == " ") return text
    // 1. 从数据库读取所有启用的脚本，按 order 排序
    val scripts = appDb.ttsScriptDao.all.filter { it.isEnabled }.sortedBy { it.order }
    if (scripts.isEmpty()) return text
    
    var result = text
    scripts.forEach { script ->
        if (script.code.isBlank()) return@forEach
        try {
            // 2. 用 Rhino JS 引擎执行脚本
            val jsResult = RhinoScriptEngine.run {
                val bindings = buildScriptBindings { bindings ->
                    bindings["java"] = ttsJsExtensions    // JS 扩展方法
                    bindings["cache"] = CacheManager      // 缓存管理
                    bindings["cookie"] = CookieStore      // Cookie 存储
                    bindings["text"] = result             // 当前文本（可修改）
                    bindings["source"] = ReadAloud.httpTTS // 当前 TTS 引擎
                    bindings["speakText"] = text          // 原始文本（只读）
                }
                eval(script.code, bindings)
            }
            // 3. 如果脚本有返回值，用它替换当前文本
            if (jsResult != null) {
                result = jsResult.toString()
            }
        } catch (e: Exception) {
            AppLog.put("朗读脚本[${script.name}]执行错误", e)
        }
    }
    return result
}
```

### 2.4 JS 执行环境

朗读脚本运行在 Rhino JS 引擎中，可用的内置变量：

| 变量名 | 类型 | 说明 |
|---|---|---|
| `text` | `String` | 当前经过前面脚本处理后的文本，**脚本应该修改并返回这个变量** |
| `speakText` | `String` | 原始文本（未被任何脚本修改），只读 |
| `source` | `HttpTTS` | 当前使用的 TTS 引擎对象 |
| `java` | `JsExtensions` | Java 扩展方法集合，可调用 `ajax`、`readFile`、`writeTxtFile` 等 |
| `cache` | `CacheManager` | 缓存管理器 |
| `cookie` | `CookieStore` | Cookie 存储 |

**脚本的返回值**：任何非 null 返回值都会被转换成字符串，替换 `text` 进入下一个脚本或 TTS 流程。

## 四、如何在自己的项目中集成

### 步骤 1：添加实体类和 DAO

1. 创建 `data/entities/TtsScript.kt`
2. 创建 `data/dao/TtsScriptDao.kt`
3. 在 `AppDatabase.kt` 的 `@Database(entities = [..., TtsScript::class])` 中注册实体
4. 在 `AppDatabase` 抽象类中添加：
   ```kotlin
   abstract val ttsScriptDao: TtsScriptDao
   ```

### 步骤 2：添加核心执行逻辑

在 `BaseReadAloudService.kt`（或你的朗读 Service 基类）中添加：

```kotlin
/**
 * 应用朗读脚本，按顺序执行启用的JS脚本，修改待朗读文本。
 */
protected fun applyTtsScripts(text: String): String {
    if (text.isEmpty() || text == " ") return text
    val scripts = try {
        appDb.ttsScriptDao.all.filter { it.isEnabled }.sortedBy { it.order }
    } catch (e: Exception) {
        return text
    }
    if (scripts.isEmpty()) return text
    var result = text
    scripts.forEach { script ->
        if (script.code.isBlank()) return@forEach
        try {
            val jsResult = RhinoScriptEngine.run {
                val bindings = buildScriptBindings { bindings ->
                    bindings["java"] = ttsJsExtensions
                    bindings["cache"] = CacheManager
                    bindings["cookie"] = CookieStore
                    bindings["text"] = result
                    bindings["source"] = ReadAloud.httpTTS
                    bindings["speakText"] = text
                }
                eval(script.code, bindings)
            }
            if (jsResult != null) {
                result = jsResult.toString()
            }
        } catch (e: Exception) {
            AppLog.put("朗读脚本[${script.name}]执行错误", e)
        }
    }
    return result
}
```

**注意**：`ttsJsExtensions` 需要在 `BaseReadAloudService` 中定义：

```kotlin
private val ttsJsExtensions by lazy {
    object : JsExtensions {
        override fun getSource() = ReadAloud.httpTTS
        override fun getTag() = "TTS"
    }
}
```

### 步骤 3：在朗读流程中调用

在 **在线朗读**（`HttpReadAloudService`）和 **系统 TTS 朗读**（`TTSReadAloudService`）中，在获取/合成音频前调用：

```kotlin
// HttpReadAloudService.kt
val segmentText = applyTtsScripts(rawText)
val speakText = purifySpeakText(segmentText)

// TTSReadAloudService.kt
val text = applyTtsScripts(segments[i])
if (text.matches(AppPattern.notReadAloudRegex)) continue
```

## 五、脚本编写指南

### 5.1 最简单的脚本

```javascript
// 删除所有 "【...】" 标记
result = text.replace(/【[^】]*】/g, '');
result;
```

**说明**：
- `text` 是输入变量（当前段落文字）
- `result` 是输出变量（修改后的文字）
- 最后一行 `result;` 是返回值，会被当成新的 `text` 传给下一个脚本或 TTS 引擎

### 5.2 多行处理示例

```javascript
// 在中文句号后加换行，让 TTS 停顿更明显
result = text.replace(/。/g, '。\n');
result;
```

### 5.3 使用 java 扩展方法

```javascript
// 调用 java.ajax 请求网络 API 进行文本分析
var resp = java.ajax('https://api.example.com/analyze?text=' + encodeURIComponent(text));
var json = JSON.parse(resp);
result = json.correctedText || text;
result;
```

**可用的 java 方法**（取决于 `JsExtensions` 实现）：
- `java.ajax(url)` — 发送 HTTP 请求
- `java.readFile(path)` — 读取本地文件
- `java.writeTxtFile(path, content)` — 写入本地文件
- 等等...

### 5.4 多个脚本配合

脚本按 `order` 顺序执行，可以组合使用：

| 顺序 | 脚本名称 | 作用 |
|---|---|---|
| 1 | 清理段评 | 删除 `袮`、`꧁` 等占位符 |
| 2 | 多音字纠正 | 把 `长` 根据上下文替换为 `zhǎng` 或 `cháng` |
| 3 | 添加停顿 | 在对话前后加空白 |

### 5.5 调试技巧

脚本执行出错时，错误信息会记录到 APP 日志中：
```
朗读脚本[脚本名称]执行错误: xxx
```

可以在脚本中加临时标记来确认执行：
```javascript
// 调试用：在文本开头标记
result = '[脚本已执行]' + text;
result;
```

## 七、注意事项

1. **脚本在后台线程执行**：不要操作 UI，错误只会记录日志不会弹窗。
2. **每个段落独立执行**：脚本看不到前后段落，只能基于当前 `text` 做处理。
3. **执行顺序很重要**：先执行的脚本修改后的结果会传给后执行的脚本。
4. **返回值必须是字符串**：如果返回 `null`，则保持原文字不变。
5. **网络请求要控制频率**：如果脚本里调用了 `java.ajax()`，注意不要在每个段落都发请求，可能会被封 IP。
6. **数据库自动迁移**：Room 数据库从旧版本升级时，`TtsScript` 表会自动创建，无需手动处理。

## 八、总结

朗读脚本功能的核心设计非常简洁：

1. **数据层**：一个 Room 实体 + DAO，存储脚本名称、代码、启用状态和排序
2. **功能层**：`BaseReadAloudService.applyTtsScripts()` 用 Rhino JS 引擎按顺序执行脚本
3. **UI 层**：列表 + 编辑两个 Activity，支持增删改查、拖拽排序、批量操作、导入导出

所有与具体文本处理相关的逻辑都写在 JS 脚本里，APP 只提供执行环境。这样用户不需要重新编译 APK，就能实现各种自定义的朗读文本处理需求。
