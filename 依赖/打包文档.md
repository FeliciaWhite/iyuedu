# 打包文档（legado / 阅读 App 正式版 APK）

本文记录从零搭建 Android 构建环境、把当前项目打包成正式版（release）APK 所需的依赖、打包过程与注意事项。
本机实测环境：Debian 13，已成功产出 `legado_app_3.26.081207.apk`（约 19.5MB，v1/v2/v3 签名验证通过）。

---

## 一、需要的依赖

### 1. JDK（Java 开发工具包）
- **版本要求**：JDK 17 或以上（AGP 8.13 要求 JDK 17+）。
- **本机实测**：Debian 13 官方源已无 `openjdk-17-jdk`，直接使用 **OpenJDK 21**（`openjdk-21-jdk-headless`）。
  - 路径：`/usr/lib/jvm/java-21-openjdk-amd64`
  - 关键属性：`sourceCompatibility = JavaVersion.VERSION_21`、`targetCompatibility = JavaVersion.VERSION_21`
- 安装命令：
  ```bash
  sudo apt update
  sudo apt install -y openjdk-21-jdk-headless
  java -version   # 确认输出 openjdk 21.x
  ```

### 2. Android SDK
- 安装方式：`cmdline-tools` + `sdkmanager` 命令行安装（无需 Android Studio）。
- 本机 SDK 目录：`/opt/android-sdk`
- 必须安装的组件：
  - `cmdline-tools;latest` —— sdkmanager 命令行工具
  - `platform-tools` —— adb 等
  - `platforms;android-36` —— 对应 `compileSdk = 36`
  - `build-tools;36.0.0` —— 对应 `buildToolsVersion`（本机同时装有 35.0.0 与 36.0.0）
  - `licenses` —— 接受所有许可（否则构建会报错）

- 通过 sdkmanager 安装示例：
  ```bash
  export ANDROID_SDK_ROOT=/opt/android-sdk
  export PATH=$PATH:$ANDROID_SDK_ROOT/cmdline-tools/latest/bin:$ANDROID_SDK_ROOT/platform-tools

  sdkmanager "cmdline-tools;latest" "platform-tools" \
             "platforms;android-36" "build-tools;36.0.0"
  sdkmanager --licenses   # 一路输入 y 接受全部许可
  ```

### 3. Gradle（构建工具）
- **版本**：Gradle 8.14.3（由项目 `gradle/wrapper/gradle-wrapper.properties` 指定）。
- 本项目已使用腾讯云镜像下载 Gradle 分发包，无需手动安装：
  - 镜像：`https://mirrors.cloud.tencent.com/gradle/gradle-8.14.3-bin.zip`
- 实际调用方式：始终用项目根目录的 `./gradlew`（wrapper 自动下载并缓存到 `GRADLE_USER_HOME`）。
  - **依赖缓存目录**：`GRADLE_USER_HOME=/workspace/依赖`（所有 Maven 依赖、Gradle 本身都缓存在这里）。
  - 设置方式（构建前导出环境变量）：
    ```bash
    export GRADLE_USER_HOME=/workspace/依赖
    ```

### 4. 第三方 Maven 依赖（已缓存于 /workspace/依赖）
- 通过 Version Catalog 管理：`gradle/libs.versions.toml`
- 关键库版本（本项目）：
  - AGP（Android Gradle Plugin）：**8.13.2**
  - Kotlin：**2.3.0**
  - KSP：**2.3.4**
  - ExoPlayer / Media3：**1.8.0**
  - 其他：协程、EventBus、Gson、Room、OkHttp 等（详见 `libs.versions.toml`）
- 这些依赖初次构建时会自动从配置的国内镜像下载并缓存到 `/workspace/依赖`，无需手动下载。

## 二、打包过程

### 步骤 1：安装 JDK 与 Android SDK
按上文“需要的依赖”装好 JDK 21、cmdline-tools，并用 sdkmanager 安装 SDK 组件、接受 licenses。

### 步骤 2：配置 local.properties
在项目根目录创建 `local.properties`，指向 SDK 目录：
```properties
sdk.dir=/opt/android-sdk
```
（`gradle.properties` 中已配置签名信息，见下文。）

### 步骤 3：配置签名（release.keystore）
项目 `gradle.properties` 已内置正式签名配置（v1/v2/v3），无需每次手动输入：
```properties
RELEASE_STORE_FILE=/workspace/release.keystore
RELEASE_STORE_PASSWORD=legado123
RELEASE_KEY_ALIAS=legado
RELEASE_KEY_PASSWORD=legado123
```
`app/build.gradle`（或对应模块）的 `buildTypes.release` 使用 `myConfig` 签名块，启用 `v1SigningEnabled`、`v2SigningEnabled`、`v3SigningEnabled`，并开启 `minifyEnabled`（R8 混淆）与 `shrinkResources`（资源压缩）。

### 步骤 4：执行打包
在**项目根目录**下执行（务必先导出 `GRADLE_USER_HOME`）：
```bash
export GRADLE_USER_HOME=/workspace/依赖
export JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64
export ANDROID_SDK_ROOT=/opt/android-sdk

./gradlew assembleRelease
```
- 首次构建会下载全部 Maven 依赖（较慢，建议后台运行并轮询日志）。
- 构建成功后产物位于：
  ```
  app/build/outputs/apk/app/release/
  ├── legado_app_3.26.081207.apk   # 正式版 APK（已签名）
  ├── legado_app_3.26.081207.apk.idsig
  └── output-metadata.json
  ```

### 步骤 5：验证签名（可选）
```bash
apksigner verify --verbose app/build/outputs/apk/app/release/legado_app_3.26.081207.apk
# 应看到 V1 Scheme / V2 Scheme / V3 Scheme: true
```

## 三、注意事项

1. **JDK 版本**：AGP 8.13 需 JDK 17+。本机 Debian 13 无 JDK 17 包，使用 JDK 21 可正常构建（AGP 8.13 兼容）。务必在构建前导出 `JAVA_HOME` 指向 JDK 21。

2. **GRADLE_USER_HOME 必须导出**：所有依赖缓存都放在 `/workspace/依赖`，构建前务必 `export GRADLE_USER_HOME=/workspace/依赖`，否则会重新下载全部依赖。

3. **国内镜像已配置**：
   - Gradle 分发包镜像：`settings.gradle` 与 `gradle-wrapper.properties` 已指向腾讯云。
   - Maven 仓库镜像：项目 `settings.gradle`（或 `init.gradle`）已配置国内镜像，保证依赖可下载。

4. **SDK 许可**：未执行 `sdkmanager --licenses` 接受许可会导致构建失败，必须提前处理。

5. **compileSdk 与 build-tools 匹配**：`compileSdk = 36` 需安装 `platforms;android-36`；`buildToolsVersion` 用 `36.0.0`，需安装 `build-tools;36.0.0`。

6. **不要引用基类不存在的属性**：编辑朗读服务代码时，注意 `BaseReadAloudService` 中并不声明 `useWifiLock` 等子类属性。曾因误将 `if (useWifiLock) { wifiLock?.release() }` 加进基类导致编译失败（`Unresolved reference 'useWifiLock'`），已改回原始 `wifiLock?.release()`。修改公共基类代码后务必重新编译确认。

7. **长耗时构建**：完整 release 构建（下载依赖+R8 混淆）耗时较长。若交互式命令被取消，可改用后台方式：
   ```bash
   nohup ./gradlew assembleRelease > build_release.log 2>&1 &
   # 之后用 tail -f build_release.log 轮询进度
   ```

8. **产物命名**：APK 文件名由 `android.defaultConfig` 或 `applicationVariants` 中的命名规则生成（如 `legado_app_3.26.081207.apk`，版本号含日期）。如需自定义命名，修改 `app/build.gradle` 中对应 `outputFileName` 逻辑。

9. **签名安全**：`gradle.properties` 中含签名密码明文，属敏感信息。提交仓库时注意是否应加入 `.gitignore` 或用环境变量覆盖，避免泄露。
