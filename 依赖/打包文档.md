# 打包文档（legado / 阅读 App 正式版 APK）

本文记录从零搭建 Android 构建环境、把当前项目打包成正式版（release）APK 所需的依赖、离线安装包、打包过程与**踩坑注意事项**。

本机实测环境：Debian 13 + OpenJDK 21 + Android SDK 36 + Gradle 8.14.3，已成功产出 `legado_app_3.26.081307.apk`（v1/v2/v3 签名验证通过）。

---

## 一、需要的依赖

### 1. JDK（Java 开发工具包）
- **版本要求**：JDK 17 或以上（AGP 8.13 要求 JDK 17+）。
- **本机实测**：Debian 13 官方源已无 `openjdk-17-jdk`，使用 **OpenJDK 21**（`openjdk-21-jdk-headless`，通过 `apt` 安装，来自 Debian 仓库，**非独立安装包**，故未收入 `sdk-packages/`）。
  - 路径：`/usr/lib/jvm/java-21-openjdk-amd64`
  - 关键属性：`sourceCompatibility = JavaVersion.VERSION_21`、`targetCompatibility = JavaVersion.VERSION_21`
- 安装命令：
  ```bash
  sudo apt update
  sudo apt install -y openjdk-21-jdk-headless
  java -version   # 确认输出 openjdk 21.x
  ```

### 2. Android SDK（离线安装包已收入 `sdk-packages/`）
- 安装方式：`cmdline-tools` + `sdkmanager` 命令行安装（无需 Android Studio）。
- 本机 SDK 目录：`/opt/android-sdk`
- 必须安装的组件：
  - `cmdline-tools;latest` —— sdkmanager 命令行工具
  - `platform-tools` —— adb 等
  - `platforms;android-36` —— 对应 `compileSdk = 36`
  - `build-tools;36.0.0` —— 对应 `buildToolsVersion`
  - `licenses` —— 接受所有许可（否则构建会报错）

- **离线安装包**（位于本仓库 `依赖/sdk-packages/`，可直接解压使用，无需联网下载）：
  | 文件 | 内容 | 解压位置 |
  |------|------|----------|
  | `cmdline-tools.zip` | commandline-tools（latest） | `/opt/android-sdk/cmdline-tools/latest` |
  | `platform-tools.zip` | platform-tools | `/opt/android-sdk/platform-tools` |
  | `platform-android-36.zip` | platforms;android-36 | `/opt/android-sdk/platforms/android-36` |
  | `build-tools-36.0.0.zip` | build-tools;36.0.0 | `/opt/android-sdk/build-tools/36.0.0` |

  离线布署示例（解压后需把 cmdline-tools 放到 `latest` 子目录，并设置可执行权限）：
  ```bash
  mkdir -p /opt/android-sdk
  cd /opt/android-sdk
  mkdir -p cmdline-tools && unzip 依赖/sdk-packages/cmdline-tools.zip -d cmdline-tools
  mv cmdline-tools/cmdline-tools cmdline-tools/latest   # 注意目录层级
  unzip 依赖/sdk-packages/platform-tools.zip -d .
  unzip 依赖/sdk-packages/platform-android-36.zip -d .
  unzip 依赖/sdk-packages/build-tools-36.0.0.zip -d .
  chmod +x cmdline-tools/latest/bin/* platform-tools/* build-tools/36.0.0/* 2>/dev/null
  # license 仍需联网接受一次（见下方坑 1）；若有离线 license 可放入 $ANDROID_SDK_ROOT/licenses
  ```
  > 说明：JDK 与 Maven/Gradle 依赖缓存（`/workspace/依赖` 下的 `caches/`、`wrapper/` 等）体积巨大且本机特定，**未**收入仓库，初次构建会从国内镜像自动下载。

### 3. Gradle（构建工具）
- **版本**：Gradle 8.14.3（由项目 `gradle/wrapper/gradle-wrapper.properties` 指定）。
- 本项目已使用腾讯云镜像下载 Gradle 分发包，无需手动安装：
  - 镜像：`https://mirrors.cloud.tencent.com/gradle/gradle-8.14.3-bin.zip`
- 实际调用方式：始终用项目根目录的 `./gradlew`（wrapper 自动下载并缓存到 `GRADLE_USER_HOME`）。
  - **依赖缓存目录**：`GRADLE_USER_HOME=/workspace/依赖`（所有 Maven 依赖、Gradle 本身都缓存在这里）。
  - 设置方式（构建前导出环境变量）：
    ```bash
    export GRADLE_USER_HOME=/workspace/依赖
    ```

### 4. 第三方 Maven 依赖
- 通过 Version Catalog 管理：`gradle/libs.versions.toml`
- 关键库版本（本项目）：
  - AGP（Android Gradle Plugin）：**8.13.2**
  - Kotlin：**2.3.0**
  - KSP：**2.3.4**
  - ExoPlayer / Media3：**1.8.0**
  - 其他：协程、EventBus、Gson、Room、OkHttp 等（详见 `libs.versions.toml`）
- 这些依赖初次构建时会自动从配置的国内镜像下载并缓存到 `/workspace/依赖`，无需手动下载。

## 二、打包过程

### 步骤 1：安装 JDK 与 Android SDK
- JDK：`apt install openjdk-21-jdk-headless`。
- SDK：用 `sdk-packages/` 离线解压（见上文），或在线用 sdkmanager 安装组件并接受 licenses。

### 步骤 2：配置 local.properties
在项目根目录创建 `local.properties`，指向 SDK 目录：
```properties
sdk.dir=/opt/android-sdk
```
（`gradle.properties` 中已配置签名信息，见下文。）

### 步骤 3：配置签名（release.keystore）
项目 `gradle.properties` 已内置正式签名配置（v1/v2/v3），无需每次手动输入：
```properties
RELEASE_STORE_FILE=/workspace/release.keystore
RELEASE_STORE_PASSWORD=legado123
RELEASE_KEY_ALIAS=legado
RELEASE_KEY_PASSWORD=legado123
```
`app/build.gradle`（或对应模块）的 `buildTypes.release` 使用 `myConfig` 签名块，启用 `v1SigningEnabled`、`v2SigningEnabled`、`v3SigningEnabled`，并开启 `minifyEnabled`（R8 混淆）与 `shrinkResources`（资源压缩）。

> ⚠️ **签名安全**：`gradle.properties` 中含签名密码明文，属敏感信息。推送到公开仓库有泄露风险，建议用环境变量覆盖或加入 `.gitignore`。本仓库目前随代码提交，仅适合私有/可信仓库。

### 步骤 4：执行打包
在**项目根目录**下执行（务必先导出环境变量）：
```bash
export GRADLE_USER_HOME=/workspace/依赖
export JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64
export ANDROID_SDK_ROOT=/opt/android-sdk

./gradlew assembleRelease
```
- 首次构建会下载全部 Maven 依赖（较慢）。
- 构建成功后产物位于：
  ```
  app/build/outputs/apk/app/release/
  ├── legado_app_3.26.081307.apk   # 正式版 APK（已签名）
  ├── legado_app_3.26.081307.apk.idsig
  └── output-metadata.json
  ```

### 步骤 5：验证签名（可选）
```bash
/opt/android-sdk/build-tools/36.0.0/apksigner verify --verbose \
  app/build/outputs/apk/app/release/legado_app_3.26.081307.apk
# 应看到 V1 Scheme / V2 Scheme / V3 Scheme: true
```

## 三、注意事项与踩坑记录（重要！）

1. **SDK license 交互会卡死**：`sdkmanager "cmdline-tools;latest" ...` 在交互终端里会暂停等待确认，**`yes | sdkmanager ...` 管道也经常不生效**（它读的是 TTY 而非 stdin）。正确做法：先单独跑 `sdkmanager --licenses` 接受全部许可（或把 `licenses` 目录整体拷到 `$ANDROID_SDK_ROOT/licenses`），再单独安装组件。未接受 license 会在构建时直接失败。

2. **后台构建会被进程组杀掉**：在本机这种"命令返回即回收进程组"的 shell 环境下，`nohup ... &` / `setsid ... &` 都可能构建到一半被 SIGKILL。实测可靠方式是**直接前台运行** `./gradlew assembleRelease`，让命令在前台跑完（可另开终端 `tail -f build_release.log` 观察进度，日志用 `./gradlew assembleRelease > build_release.log 2>&1` 重定向）。不要依赖后台任务。

3. **Kotlin 漏 import 导致编译失败**：调用 `abs()` 时若忘了 `import kotlin.math.abs`，会报 `Unresolved reference 'abs'`。Kotlin 顶层 `abs` 来自 `kotlin.math`，**不会**自动导入。改完数学相关代码后务必重新编译确认。

4. **DialogFragment Window 触摸机制坑（本项目实测）**：
   - `FLAG_NOT_TOUCH_MODAL` **只影响触摸穿透，不影响绘制层级**——给半屏 Dialog 加这个 flag 后，其上方的全屏 Window 仍会绘制白底 `contentPanel` 把阅读文字**挡住**（白屏），且半天屏内容点不动。结论：**不要用 `FLAG_NOT_TOUCH_MODAL` 来"解决半屏点不动"**。
   - 正确做法：半屏分支用 `setLayout(MATCH_PARENT, WRAP_CONTENT)` + `gravity=BOTTOM` + `dimAmount=0` + `clearFlags(FLAG_NOT_TOUCH_MODAL)`，并在 `dialog.window.decorView` 上挂手势监听实现"下滑退出"。WRAP_CONTENT 保证 Window 只占底部内容高度，不会遮挡上方阅读文字。

5. **不要误改公共基类**：编辑朗读服务代码时，注意 `BaseReadAloudService` 中并不声明 `useWifiLock` 等子类属性。曾因误将 `if (useWifiLock) { wifiLock?.release() }` 加进基类导致 `Unresolved reference 'useWifiLock'`。修改公共基类代码后务必重新编译。

6. **JDK 版本**：AGP 8.13 需 JDK 17+。本机 Debian 13 无 JDK 17 包，使用 JDK 21 可正常构建。务必在构建前导出 `JAVA_HOME` 指向 JDK 21，否则可能用到系统其它 JDK 导致版本不符。

7. **GRADLE_USER_HOME 必须导出**：所有依赖缓存都放在 `/workspace/依赖`，构建前务必 `export GRADLE_USER_HOME=/workspace/依赖`，否则会重新下载全部依赖（极慢且可能失败）。

8. **国内镜像已配置**：Gradle 分发包（`gradle-wrapper.properties`）、Maven 仓库（`settings.gradle`）已指向国内镜像，保证依赖可下载；若换网络环境失败，检查镜像地址是否可达。

9. **compileSdk 与 build-tools 匹配**：`compileSdk = 36` 需 `platforms;android-36`；`buildToolsVersion` 用 `36.0.0`，需 `build-tools;36.0.0`。版本不匹配会直接报错。

10. **产物命名**：APK 文件名由 `app/build.gradle` 中命名规则生成（含日期，如 `legado_app_3.26.081307.apk`）。如需自定义，修改对应 `outputFileName` 逻辑。重新打包前建议先 `./gradlew clean` 确保产出是最新构建，避免误以为"打包没生效"。
