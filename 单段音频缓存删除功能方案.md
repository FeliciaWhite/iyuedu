# 单段音频缓存删除功能方案

## 一、需求理解

在阅读界面每段开头的缩进位置，显示一个**半透明小图标**，标识该段落对应的朗读音频**已经生成并存在于缓存中**。点击图标即可**单独删除该段音频缓存**，删除后图标即时消失。这样可以精准删除某一段生成错误的缓存音频，修改文本后重新朗读时会自动重新生成，无需清空全部缓存。

---

## 二、核心难点与解决思路

### 难点：排版段落 ↔ 音频缓存文件的精确映射

音频缓存文件名由**章节标题 MD5 + 段落文本 MD5 + 段落序号**组合哈希生成（`getFileNameHelper`）。`TextLine` 在排版时只知道自己的 `paragraphNum`，不知道对应音频文件路径。

### 解决思路：运行时预扫描 + 索引绑定

1. **绑定索引**：在 `TextChapterLayout` 排版时，给每段首行的 `TextLine` 打上 `audioParagraphIndex = paragraphNum - 1` 标记（对应 `BaseReadAloudService.contentList` 的索引）。
2. **预扫描状态**：新增 `AudioCacheIndicatorManager`，在章节加载完成后，根据当前朗读引擎类型（HttpTTS / 系统TTS）、语速、音色等参数，遍历 `contentList` 逐段计算预期文件名，检查缓存目录，把"有缓存的段落索引"存入一个 `Set<Int>`。
3. **绘制时查询**：`TextLine.draw()` 时直接查 `Set`，O(1) 判断是否需要绘制图标，无需文件 I/O。
4. **点击删除**：点击后从 `Set` 移除对应索引，同时删除物理文件，即时 `invalidate()` 重绘。

### 4.4 预扫描缓存状态（新建 `AudioCacheIndicatorManager.kt`）

```kotlin
object AudioCacheIndicatorManager {

    // 当前章节「有缓存的段落索引」集合
    private val cachedParagraphSet = mutableSetOf<Int>()

    // 根据当前朗读引擎参数，计算某段落的预期缓存文件名
    fun scanChapter(textChapter: TextChapter) {
        cachedParagraphSet.clear()
        val title = textChapter.title
        val contentList = textChapter.getNeedReadAloud(0, false, 0)
            .split("\n")
            .filter { it.isNotEmpty() }

        contentList.forEachIndexed { index, content ->
            if (content.isBlank()) return@forEachIndexed
            val fileName = when (当前朗读引擎类型) {
                HttpTTS -> computeHttpTtsFileName(title, content, index)
                系统TTS -> computeSystemTtsFileName(title, content, index)
                else -> null
            }
            if (fileName != null && File(fileName).exists()) {
                cachedParagraphSet.add(index)
            }
        }
    }

    fun hasCache(paragraphIndex: Int): Boolean = cachedParagraphSet.contains(paragraphIndex)

    fun deleteCache(textChapter: TextChapter, paragraphIndex: Int): Boolean {
        if (!cachedParagraphSet.contains(paragraphIndex)) return false
        val title = textChapter.title
        val contentList = textChapter.getNeedReadAloud(0, false, 0)
            .split("\n")
            .filter { it.isNotEmpty() }
        val content = contentList.getOrNull(paragraphIndex) ?: return false

        val fileName = when (当前朗读引擎类型) {
            HttpTTS -> computeHttpTtsFileName(title, content, paragraphIndex)
            系统TTS -> computeSystemTtsFileName(title, content, paragraphIndex)
            else -> return false
        }
        val deleted = File(fileName).delete()
        if (deleted) cachedParagraphSet.remove(paragraphIndex)
        // 同时删除 .seginfo 文件（如果存在）
        File("$fileName.seginfo").delete()
        return deleted
    }

    fun clearChapterState() {
        cachedParagraphSet.clear()
    }
}
```

> **注意**：文件名计算必须严格复用 `HttpReadAloudService.getFileNameHelper()` 和 `TTSReadAloudService.getFileNameHelper()` 的算法，包括语速、音色、TTS URL 等所有参与哈希的因子，否则文件名匹配会失败。

### 4.5 绘制图标（`TextLine.kt`）

在 `drawTextLine()` 和 `fastDrawTextLine()` 中，在角色标注绘制代码附近增加：

```kotlin
// 绘制音频缓存标记（在段落首行缩进左侧）
if (AppConfig.showAudioCacheIndicator
    && audioParagraphIndex >= 0
    && hasAudioCache
    && !isTitle && !isImage && !isHtml
) {
    val paint = PaintPool.obtain()
    paint.color = ReadBookConfig.textAccentColor
    paint.alpha = 80  // 比较浅，半透明
    paint.style = Paint.Style.FILL
    val radius = 3.dpToPx().toFloat()
    // 画在 startX 左侧一点的位置（缩进位置）
    val cx = startX - radius - 4.dpToPx()
    val cy = lineBase - lineTop - (lineBottom - lineTop) / 2
    canvas.drawCircle(cx, cy, radius, paint)
    PaintPool.recycle(paint)
}
```

**图标样式说明**：
- **形状**：小圆点（`drawCircle`），也可以改成小音符或垃圾桶图标
- **颜色**：`ReadBookConfig.textAccentColor`，但 `alpha = 80`（约 31% 不透明度），比较浅，不干扰阅读
- **位置**：`startX - radius - 4dp`，即缩进位置的左侧 4dp 处，圆心垂直居中于行高
- **大小**：半径 3dp，非常小巧

### 4.6 点击检测与删除（`ContentTextView.kt`）

在 `click()` 方法中，在角色标注检测之后、普通文本点击之前，增加音频缓存图标的点击检测：

```kotlin
fun click(x: Float, y: Float): Boolean {
    // ... 现有防抖代码 ...

    // 先检测角色标注点击
    if (!debounceClick && checkRoleAnnotationClick(x, y)) {
        return true
    }

    // ===== 新增：检测音频缓存标记点击 =====
    if (!debounceClick && checkAudioCacheIndicatorClick(x, y)) {
        return true
    }
    // ======================================

    // ... 现有 touch 逻辑 ...
}

private fun checkAudioCacheIndicatorClick(x: Float, y: Float): Boolean {
    if (!AppConfig.showAudioCacheIndicator) return false
    if (!visibleRect.contains(x, y)) return false

    var relativeOffset: Float
    for (relativePos in 0..2) {
        relativeOffset = relativeOffset(relativePos)
        if (relativePos > 0) {
            if (!callBack.isScroll) return false
            if (relativeOffset >= ChapterProvider.visibleHeight) return false
        }
        val textPage = relativePage(relativePos)
        for (textLine in textPage.lines) {
            if (!textLine.isTouch(x, y, relativeOffset)) continue
            if (textLine.audioParagraphIndex < 0 || !textLine.hasAudioCache) continue

            // 计算图标点击区域（以图标为中心，扩大 12dp 容错）
            val radius = 3.dpToPx() + 12.dpToPx()
            val cx = textLine.startX - 3.dpToPx() - 4.dpToPx()
            val cy = textLine.lineTop + relativeOffset + (textLine.lineBottom - textLine.lineTop) / 2
            if (x >= cx - radius && x <= cx + radius
                && y >= cy - radius && y <= cy + radius
            ) {
                val book = ReadBook.book ?: return false
                val chapterTitle = textLine.textPage.textChapter.title
                val paragraphIndex = textLine.audioParagraphIndex

                // 弹出确认对话框
                AlertDialog.Builder(context)
                    .setTitle("删除音频缓存")
                    .setMessage("是否删除该段落的音频缓存？")
                    .setPositiveButton("删除") { _, _ ->
                        val deleted = AudioCacheIndicatorManager.deleteCache(
                            textLine.textPage.textChapter, paragraphIndex
                        )
                        if (deleted) {
                            textLine.hasAudioCache = false
                            invalidate()
                            context.toastOnUi("已删除该段音频缓存")
                        } else {
                            context.toastOnUi("删除失败，文件不存在")
                        }
                    }
                    .setNegativeButton("取消", null)
                    .show()
                return true
            }
        }
    }
    return false
}
```

### 4.7 章节切换时刷新（`ReadBook.kt`）

在加载/切换章节后，调用预扫描：

```kotlin
textChapter ?: return
val bookName = book?.name ?: return
Coroutine.async(this) {
    DialogRoleManager.clearChapterCache(bookName, textChapter.title)
    DialogRoleManager.attachAnnotations(textChapter, bookName)

    // ===== 新增：预扫描音频缓存状态 =====
    AudioCacheIndicatorManager.scanChapter(textChapter)
    // 给所有 TextLine 打上 hasAudioCache 标志
    textChapter.pages.forEach { page ->
        page.lines.forEach { line ->
            if (line.audioParagraphIndex >= 0) {
                line.hasAudioCache = AudioCacheIndicatorManager.hasCache(line.audioParagraphIndex)
            }
        }
    }
    // =====================================

    withContext(kotlinx.coroutines.Dispatchers.Main) {
        callBack?.upContent()
    }
}
```

## 六、关键注意事项

1. **文件名哈希因子必须一致**：`AudioCacheIndicatorManager` 计算文件名时，必须复用现有 `getFileNameHelper` 的所有输入因子（语速 `speechRate`、段落序号 `index`、段落文本 `content`、章节标题 `title`，以及系统TTS的引擎/音色/速率）。如果因子不一致，会导致"文件存在但检测不到"或"删错文件"。

2. **多引擎兼容性**：用户可能在 HttpTTS 和系统TTS 之间切换。`scanChapter()` 应该只扫描**当前生效引擎**的缓存目录，避免误标。切换引擎后，旧引擎的缓存标记不再显示。

3. **并发安全**：`scanChapter()` 和 `deleteCache()` 可能在不同线程调用，对 `cachedParagraphSet` 的读写需要加锁（或复制快照）。

4. **性能**：`scanChapter()` 遍历 `contentList` 逐段做 MD5 并检查文件存在性，如果段落很多（如几百段），可能会有短暂卡顿。建议放在 `IO` 线程执行（已在 `ReadBook.kt` 的 `Coroutine.async` 中）。

5. **图标位置不要和角色标注重叠**：角色标注画在行上方，音频缓存标记画在行左侧缩进处，两者空间不冲突。

6. **删除后即时反馈**：删除文件后必须立即 `invalidate()`，否则图标不会消失。同时需要更新 `cachedParagraphSet` 防止重复删除。

## 七、与你现有代码的关联

该功能和**角色标注**是独立但并列的两个功能：
- 角色标注：依赖 AI 分析的 JSON 缓存，画在**行上方**，点击编辑角色信息
- 音频缓存标记：依赖 TTS 音频文件，画在**行左侧缩进处**，点击删除音频

两者共用相似的架构（`TextLine` 新增字段 + `ContentTextView` 点击检测 + `ReadBook.kt` 章节加载钩子），可以一起参考角色标注的实现方式来开发。
